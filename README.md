## What it is

A wallet-safety agent for BSC mints ("screen a mint before you sign"). It checks a
contract address against public sources: does it have bytecode on BSC? Is the source
verified on Sourcify? It fails closed — unverified means caution, never a green light.
This matches Ban's real mint workflow (DYOR + preflight before every mint).

### Protocol-v1 (applies to the endpoint whenever it is registered / preflighted)
- `POST {registered URL}` with a signed JSON envelope. **Register the full handler
  path** (e.g. `/agent`), not just the root — a root that 404s fails preflight.
- **Inbound:** HMAC over the RAW request body, compared to the
  `x-agent-games-signature` header BEFORE parsing JSON. Reject (401) on mismatch.
- **Outbound:** every 200 response carries `x-agent-games-signature` over the raw
  response body. Response bodies ≤ 16 KB. Preflight must answer within **10 s**;
  tasks have a **60 s** hard deadline.
- **Preflight envelope:** `{"type":"agent-games.preflight.v1","agent_id":"agt_…","issued_at":"…","nonce":"…"}` → respond `{"ok":true,"protocolVersion":"v1"}` (signed). Must pass before the platform marks the agent active.
- **Gatekeeper envelope:** `{"type":"agent-games.proof-gatekeeper.v1","task_id":"gk_…","mode":"competition","issued_at","deadline_at","input":{registered_vk, proof_vk, minimum, public_balance, expiry_block, current_block, recipient, amount, max_transfer, proof_tx}}` → respond `{"decision":"APPROVE"|"REJECT","reason_code","proof_tx"}` (+ Groth16 `proof`/`public_signals` on provable tasks; omitted/invalid proof costs −2).
- **Steal the VFY turn envelope:** `{"protocolVersion":"v1","eventId":"steal-the-vfy","matchId","turn","issuedAt","deadlineAt","state":{selfBalance, opponentBalance, selfFortifiedUntilTurn, opponentFortifiedUntilTurn},"strategyCommitment":{"hash"},"resolverVersion":"v1","nonce"}` → respond `{"matchId","turn","action":{"type":"HOLD"|"FORTIFY"|"EXTRACT","amount"?},"policyProof":{"circuitVersion":"v1","proof":{…},"public_signals":[…],"proofReference"?,"publicInputsHash"?},"agentTimestamp","idempotencyKey"}`. Missing/mismatched field = HOLD with no proof. `action.amount` must be OMITTED for HOLD/FORTIFY. Never reuse an `idempotencyKey` across turns.
- **Idempotency:** task IDs are idempotency keys; the platform may retry after network failure. This server persists responses in `seen.json` (capped at 500) and replays them.
- **HMAC secret:** 32-byte random, generated by the platform, shown ONCE via dashboard "Rotate Secret". Set as `AGENT_GAMES_HMAC_SECRET` (here: `secret.env`, 0600). A mismatched/placeholder secret fails preflight with a signature error.

### What this agent handles — and what it does NOT
- ✅ Preflight handshake (signed `{ok:true, protocolVersion:"v1"}`).
- ✅ HMAC verify (inbound) + sign (outbound), idempotent replays, request logging.
- ✅ Gatekeeper tasks: **fail-closed REJECT** (`reason_code: "PROOF_NOT_GENERATED"`, echoes `proof_tx`). Never approves a transfer it cannot prove.
- ✅ Steal the VFY turns: **HOLD with no proof** (honest fail-closed; per spec a turn with no proof scores as an invalid-proof HOLD, −2).
- ✅ Generic/unknown envelopes: signed echo `{ok:true, protocolVersion:"v1", taskId, handled:false, reason:"unsupported_task_type"}`.
- ✅ Public demo `POST /check`: BSC contract screen (bytecode via public BSC RPC + Sourcify v2 verification status). Verified live: PancakeSwap router → `SAFER`; EOA → `UNSAFE`.
- ❌ **No Groth16 proof generation.** The arena tracks need local proof generation with the platform's circuits (gatekeeper.wasm/zkey, vfy-policy.wasm/zkey — downloadable from /build) + zkVerify submission (Kurier API key or funded zkVerifyJS account). The circuit input mapping is not in the public docs I could read, and no Kurier key / funded account exists. So this agent is **not arena-competitive**; it is fail-closed by design. Entering an arena event with it would lose every scored task (REJECT/HOLD). For Wildcard that does not matter — Wildcard is judged on the build, not on live tasks.
- ❌ No zkVerify proof attached to the Wildcard entry (optional bonus not implemented; the agent's claims are checkable via public Sourcify + BSC RPC reads instead).

### HMAC scheme — one genuine unknown
The /build page never states the digest algorithm or encoding. This server uses
**HMAC-SHA256, hex-encoded, key = the secret string as UTF-8 bytes** (the standard
Node convention). Inbound verification also tries the secret hex-decoded and
base64-decoded as key material and logs WHICH candidate matched (`sigCandidate` in
`dispatch.log`), so the first real preflight attempt is the oracle: if the platform
uses a different encoding, the log shows the mismatch and the fix is a one-line
change in `server.mjs` (`signBody`). Do not guess further — test with preflight.

## Deployment (why this shape)

- The VM has **no public IP** (CGNAT `198.19.0.2` + ULA IPv6 only) and all egress
  goes through an HTTP proxy. Direct inbound is impossible.
- **cloudflared quick tunnel: BLOCKED.** `api.trycloudflare.com` returns 403 from
  the egress proxy (allowlist), so `cloudflared tunnel` fails with a TLS error.
  A named Cloudflare tunnel would need a Cloudflare account + token (browser step).
- **Tailscale Funnel: unavailable.** The built-in client is client-only (accepts
  no connections, hosts nothing); `funnel`/`serve` are explicitly unavailable and
  installing another client is forbidden. The VM is not joined to any tailnet.
- **localhost.run (SSH remote-forward): WORKS.** Free, no account. `ssh -R
  80:localhost:8080 nokey@localhost.run` via a CONNECT tunnel through the egress
  proxy (`proxy-command.mjs`, credentials read from env, never logged). Public URL
  `https://705c2ba9698e2d.app.lhr.life` (TLS terminated by localhost.run, port 443).
  Verified end-to-end from the public internet (health, demo page, preflight,
  /check) on 2026-11-19.
- **Caveats:** the free `*.app.lhr.life` domain **rotates periodically** (stated in
  the tunnel banner) and changes on every reconnect. A stable domain needs a free
  localhost.run account + key (see https://localhost.run/docs/forever-free/) or a
  custom-domain plan. If the URL changes, re-register the endpoint in the
  dashboard (Edit agent → save re-runs preflight) and update the Wildcard
  submission's endpoint field.
- **No crontab on this VM**, so there is no @reboot hook. Recovery is manual (below).

## Running it

```
cd ~/workspace/agentgames/agent
./start.sh          # supervisor: starts server (port 8080) + tunnel, restarts either if it dies
```
- `start.sh` runs a supervisor loop (checks every 20 s). Run detached:
  `setsid nohup ./start.sh > supervisor.log 2>&1 < /dev/null &`
- Live processes: `node server.mjs` (port 8080), `ssh … nokey@localhost.run`,
  `bash ./start.sh`. Current public URL is in `tunnel.url`.
- Logs: `server.log`, `tunnel.log`, `dispatch.log` (JSON lines, no secrets),
  `supervisor.log`. Idempotency store: `seen.json`.

## Setting the HMAC secret (after agent registration, browser step)

1. Dashboard → My Agents → (agent) → Rotate Secret → copy the one-time plaintext.
2. Paste it into `secret.env` as `AGENT_GAMES_HMAC_SECRET=<plaintext>` (file is 0600).
3. Restart the server: `kill $(cat server.pid)` — the supervisor restarts it within ~20 s (or `kill <pid>` of the `node server.mjs` process).
4. Dashboard → run preflight. It must pass before the agent is marked active.
   If it fails with a signature error, check `dispatch.log` `sigCandidate` and
   see "HMAC scheme" above.

## Recovery (VM restart / tunnel drop / domain rotation)

1. `cd ~/workspace/agentgames/agent && setsid nohup ./start.sh > supervisor.log 2>&1 < /dev/null &`
2. Wait ~30 s, then read the new URL: `cat tunnel.url` (and verify:
   `curl -s https://<url>/health`).
3. If the URL changed: dashboard → My Agents → Edit agent → set the new endpoint
   URL → save (re-runs preflight); and Dashboard → Submissions → Wildcard entry →
   update the endpoint field.
4. If the server itself won't start: `node --check server.mjs`; check `server.log`.
